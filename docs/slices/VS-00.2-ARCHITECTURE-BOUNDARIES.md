# VS-00.2 — Architecture Boundary Enforcement

Status: Implemented; awaiting Product Owner acceptance

## Goal

Normalize executable project-boundary checks for the implemented V2 modular-monolith topology without changing runtime behaviour or creating future modules.

## Governing decisions and acceptance criteria

- VS-00 acceptance criteria 1, 2, 5 and 13.
- ADR-0001 — Modular Monolith with Vertical Slices.
- ADR-001 — Module, PostgreSQL Schema, DbContext and Migration Ownership.

## Enforced dependency rules

The architecture test discovers all projects below `src/` and reports every forbidden dependency as a clear `source -> target` edge.

1. Source projects may not reference an application host under `apps/`.
2. BuildingBlocks may not reference a module implementation.
3. A module may not reference another module's implementation.
4. A domain project may not reference an infrastructure project.
5. A domain project may not reference EF Core or Npgsql persistence packages.

The API remains the composition root and may reference implemented modules. Infrastructure may reference its own module/domain project and framework or provider packages.

## Implementation evidence

- `tests/NoorPath.Architecture.Tests/FoundationTests.cs` inspects checked-in project references and package references using standard .NET APIs.
- `NoorPath.slnx` remains the repository-root marker and retains the existing proportionate project topology.
- No architecture-testing package or new runtime abstraction is introduced.

## Validation

Run:

```bash
dotnet test tests/NoorPath.Architecture.Tests/NoorPath.Architecture.Tests.csproj --nologo
dotnet test NoorPath.slnx --nologo
dotnet build NoorPath.slnx --no-restore --nologo
dotnet format NoorPath.slnx --no-restore --verify-no-changes
git diff --check
```

## Explicit non-goals and deferred debt

- Do not create projects for future modules.
- Do not move API endpoints or change runtime composition in this slice.
- Do not change database models, migrations or persistence behaviour.
- Defer the Catalogue/Pricing/Inventory ownership split to its separately approved slice.
- Defer module-to-module public contract exceptions until a real cross-module use case requires an explicit contract and corresponding architecture rule.
- Direct SQL or runtime data-access violations remain subject to focused review and integration tests; project-reference inspection cannot prove SQL schema ownership.
