# VS-00.1 — Persistence Foundation Reset

Status: In progress

## Goal
Replace the fragile S02 EF migration foundation with deterministic, EF-owned migration artifacts and a reusable migration-integrity gate before any V2 feature persistence evolves further.

## Constraints
- Do not merge while the model snapshot delegates to the live `CatalogueDbContext` model.
- Do not treat the existing mixed Catalogue/Pricing/Inventory model as the final V2 ownership model.
- Preserve Git history instead of trying to rewrite old merged commits.
- Use PostgreSQL-backed integration tests as real migration/application evidence.

## Execution
1. Align EF/Npgsql tooling versions.
2. Add reusable pending-model-change validation.
3. Replace hand-maintained migration metadata with frozen EF-style migration metadata/snapshot artifacts.
4. Run clean-database migration and pending-model-change checks in CI.
5. Before VS-02/VS-03 feature persistence resumes, split Pricing and Inventory authority out of Catalogue in accordance with ADR-001.

## Exit criteria for VS-00.1
- Snapshot is a frozen model, not `CatalogueDbContext.Configure(modelBuilder)`.
- Initial migration has matching migration metadata/designer artifact.
- `dotnet ef migrations has-pending-model-changes` succeeds.
- Clean PostgreSQL database migrates successfully in CI.
- Integration tests use the migration path rather than schema shortcuts.
- The known Catalogue/Pricing/Inventory ownership split remains an explicit follow-on foundation task, not hidden debt.
